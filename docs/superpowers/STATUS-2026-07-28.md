### ⚠ Gotchas from this stretch — root causes, so they don't recur
1. **A cross-cutting overlay must fail safe.** `CoachMarks` read a provider
   depending on `sharedPreferencesProvider`; widget tests don't override it, so
   every habit-screen test died with `UnimplementedError` inside a post-frame
   callback. **Rule:** a tutorial/overlay must never be able to break the screen
   it decorates — wrap its entry point in try/catch and render the child anyway.
2. **Never run a formatter wider than your edit.** `dart format lib/features/`
   reformatted **131 unrelated files** (5.6k insertions). Recovery:
   `git diff --name-only | grep -v -E "<my files>" | xargs git checkout --`.
   **Rule:** format only the files you touched.
3. **A green test can be encoding the bug.** The notes drag suite asserted that
   dropping at the end of a bed *keeps you inside* — which was exactly the bug.
   **Rule:** when a fix makes an old test fail, first ask whether that test was
   asserting the defect, and say so out loud before changing it.
4. **Boundary tie-breaks need the original position.** "End of bed" and "after
   bed" are the same gap; breaking the tie toward OUT would eject an *unmoved*
   last line, so `resolveDrop` takes `originalGap`/`originalIndent` and treats a
   no-move drop as a no-op. The **live preview must pass the same arguments** as
   the commit, or the drop indicator lies about where the block will land.
5. **Z Flip cover screen is a Samsung-curated catalogue** — full evidence in
   `specs/2026-08-04-flip-cover-screen-feasibility.md`. `widgetCategory=keyguard`
   is necessary but NOT sufficient; only Samsung/Google/Microsoft packages hold
   cover tiles. Route A (in-app compact layout) is the viable path.

## 2026-08-22 — widget showed the previous day (v1.16.0)

User: *"the widget sometimes shows the previous day because it didn't refresh."*
Two faults compounding, and the second is the one that mattered.

### Gotcha: `updatePeriodMillis="0"` means the widget NEVER redraws itself
All three widget XMLs set it to 0, so the only redraw triggers were an app push
(launch/resume/pause), a tap on ‹ › or a day, and the launcher rebinding. With
the app closed, the last push was frozen on screen indefinitely.

### Gotcha (the real one): date-relative text was baked at PUSH time
`month_cells[].kind = 'today'`, `today_date`, `widget_today` and every task
row's `label` ("Today"/"Tomorrow"/"Overdue · 3 Aug") were all composed in Dart
and stored as finished strings. So even a redraw would have shown yesterday.
**Rule: a surface that outlives the process must not cache anything relative to
"now" — store the raw date and decide what it means while drawing.**

Fallout of the same bug: `applyOffset` resolved the visible month with a *live*
`Calendar.getInstance()` while the cells were built against Dart's stale `now`,
so after a month rollover the grid moved to the new month with **no day
highlighted at all**.

### Gotcha: `ACTION_DATE_CHANGED` cannot be used to catch midnight
The obvious fix is a manifest receiver for it. Verified against Android's
implicit-broadcast exemption list: `TIME_SET`, `TIMEZONE_CHANGED`,
`NEXT_ALARM_CLOCK_CHANGED`, `LOCALE_CHANGED` and `BOOT_COMPLETED` are exempt —
**`DATE_CHANGED` is not**, so a manifest-declared receiver never sees it on
Android 8+. Only a runtime-registered receiver would, which needs a live
process, which is exactly what is missing. `updatePeriodMillis` is the other
trap: 30-minute floor, wakes the device, and wouldn't have fixed the baking.

### Fix
`WidgetDates.kt` resolves today at draw time for all three widgets **and** the
live notification header; `MidnightRefreshReceiver` books an **inexact**
`setAndAllowWhileIdle` for 00:01 and re-books itself (plus on BOOT_COMPLETED,
TIME_SET, TIMEZONE_CHANGED, and every app launch). Inexact is enough precisely
*because* the drawing is date-live — see roadmap **G4** for the exact-alarm /
Play-policy question the user wants revisited.

### Efficiency
`sync()` runs on launch, every resume and every pause. It now composes the
whole payload, checksums it (FNV-1a — **not** `String.hashCode`, which is not
guaranteed stable across processes, and this value is compared against one
written by an earlier launch), and returns without writing when nothing
changed. Skips ~13 preference commits and 3 widget redraws per redundant call.
